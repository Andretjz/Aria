# ADR-003: Adapter Pattern for All External Services

**Status**: Accepted
**Date**: 2026-05-16
**Decided by**: Sam_Architect + Claude gate review

## Context

Aria depends on multiple external services (STT, LLM, TTS, diarization, translation) that may be swapped as the market evolves, as better providers emerge, or as cost structures change. Coupling business logic directly to provider SDKs creates high migration costs and makes testing difficult.

## Decision

Every external service is wrapped behind an abstract base class in `services/interfaces.py`. Concrete implementations live in `services/providers/`. The factory in `services/factory.py` is the only place that reads `.env` to select a provider. Business logic imports from the factory via FastAPI `Depends()` — never from a provider directly.

**Standard shape** (all services follow this pattern):
```python
# Business logic — zero provider knowledge
@router.websocket("/ws/conversation/{session_id}")
async def conversation(
    ws: WebSocket,
    stt: STTService = Depends(get_stt_service),
    llm: LLMService = Depends(get_llm_service),
    tts: TTSService = Depends(get_tts_service),
): ...
```

**Swapping a provider = one .env change**:
```bash
STT_BACKEND=deepgram  # was: gladia
```
No code changes. No redeployment of business logic. Only the factory reads this variable.

## Consequences

**Positive**:
- Provider migrations take minutes, not weeks
- Business logic is testable with mock implementations of the abstract interfaces
- Adding a new provider = one new file in `services/providers/`
- Quinn_QA can enforce the rule mechanically: no `from aria.services.providers.*` in any module

**Negative/Risk**:
- Every new provider must implement the full abstract interface — no partial implementations
- Async generator interfaces (`AsyncIterator[bytes]`) are slightly more complex than synchronous equivalents

**Mitigated by**: The abstract interfaces are designed to be minimal. Each has at most 2 abstract methods. The `generate_complete()` convenience method on `LLMService` is implemented once on the base class, not on every provider.

## Alternatives Rejected

| Alternative | Why rejected |
|---|---|
| Direct SDK imports in business logic | Any provider change requires touching every file that imports the old SDK |
| Dependency injection framework (e.g., injector) | Overkill; FastAPI's built-in Depends() is sufficient |
| Plugin-based dynamic loading | Too complex; .env-based factory selection is simpler and equally flexible |
