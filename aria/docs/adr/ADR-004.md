# ADR-004: React + TypeScript over Vanilla JS

**Status**: Accepted
**Date**: 2026-05-16
**Decided by**: Sam_Architect + Claude gate review

## Context

Transcribit used vanilla JavaScript. Aria has 6 product modules, each with complex interactive state: live audio waveform, real-time transcript, flashcard flip animations, comprehension quiz hide/reveal, SM-2 progress charts, grammar deficit bars. Vanilla JS becomes unmanageable at this scale.

## Decision

**React 18 + TypeScript** with Vite as the build tool.

- **React 18**: Concurrent rendering, Suspense for async data loading, built-in state management primitives. Large ecosystem for accessible UI components.
- **TypeScript**: Type-safe interfaces between frontend and backend schemas. Catches API contract mismatches at build time. Required by the project's type-safety standard.
- **Vite**: Sub-second HMR in development, fast production builds with Rollup, native ESM.
- **Zustand**: Minimal state management — simpler than Redux, works well with React 18 concurrent features.
- **shadcn/ui + Radix UI**: Accessible, unstyled primitives that compose with Tailwind tokens. Radix handles focus trapping, keyboard navigation, and ARIA automatically.

## Consequences

**Positive**:
- Component reuse across 6 modules (e.g., `ComprehensionQuiz` appears in Modules 1, 2, 4)
- TypeScript catches API schema mismatches before they reach production
- Vitest shares the Vite config — no separate Jest setup needed

**Negative/Risk**:
- Larger initial bundle than vanilla JS (~150KB gzipped baseline React runtime)
- JSX compilation step adds build complexity vs. plain HTML

**Mitigated by**: Vite code splitting per route keeps each module's JS chunk small. Lazy imports with `React.lazy()` deferred by Fiona_Frontend in Phase 7.

## Alternatives Rejected

| Alternative | Why rejected |
|---|---|
| Vanilla JS (continue Transcribit approach) | Unmanageable at 6-module scale with complex state interactions |
| Vue 3 | Smaller ecosystem for accessible UI components; team (Claude) has deeper React expertise |
| Svelte | Excellent DX but smaller component library ecosystem; Radix UI is React-only |
| Next.js | SSR overhead not needed for an authenticated SPA; Vite is simpler |
