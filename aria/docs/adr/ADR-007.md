# ADR-007: Fly.io for Backend Hosting

**Status**: Accepted
**Date**: 2026-05-16
**Decided by**: Sam_Architect + Claude gate review

## Context

Aria requires: WebSocket support without 30-minute timeouts, Docker-native deployment, global edge for EU users, cost-effectiveness for an early-stage product, and simple CI/CD from GitHub Actions.

## Decision

**Fly.io** for the FastAPI backend. **Vercel** for the React frontend (separate decision — corollary of ADR-004).

Production container spec: 2 shared CPU, 4GB RAM.

**Why Fly.io**:
- Docker-native: `fly deploy` from GitHub Actions, no custom K8s config
- WebSocket-friendly: no 30-minute timeout (unlike Cloud Run, Heroku)
- Global edge: Frankfurt region for EU GDPR data residency
- Cost: ~$10–20/month for 2 CPU / 4GB — within budget for MVP
- Nginx built-in via `[services]` config: WebSocket upgrade, HSTS, CSP headers
- `fly secrets` for env var management — no `.env` files in production

**Why Vercel** (frontend):
- Zero-config React/Vite deployment
- Global CDN, free tier, auto-deploys from `main` branch on every push
- No server required — static assets only

## Consequences

**Positive**:
- `fly deploy` in CI is 3 lines of GitHub Actions config
- Fly.io scales to 0 during low traffic (cost savings)
- Both Fly.io and Vercel have generous free tiers for initial launch

**Negative/Risk**:
- Fly.io has had occasional platform incidents (smaller than AWS/GCP)
- 2 shared CPU may be insufficient under load (upgrade path: 4 shared CPU, ~$30/month)

**Mitigated by**: Phase 8 load test (10 concurrent Locust users) verifies the spec is sufficient. If p95 > 5s, Dmitri_DevOps upgrades the machine spec before Gate 8 approval.

## Alternatives Rejected

| Alternative | Why rejected |
|---|---|
| AWS ECS/Fargate | 3-4× cost; significantly more configuration overhead |
| Google Cloud Run | 30-minute WebSocket timeout — incompatible with live conversation sessions |
| Railway | WebSocket support but less reliable than Fly.io; smaller community |
| Azure Container Apps | Higher cost; complex networking for WebSocket upgrades |
| Self-hosted VPS | Maintenance burden; no managed TLS, no auto-scaling |
