# ADR-006: SQLite (Dev) → Supabase/PostgreSQL (Production)

**Status**: Accepted
**Date**: 2026-05-16
**Decided by**: Sam_Architect + Claude gate review

## Context

The dev/test database needs to be fast to set up (no external service, no Docker container required for unit tests), while production needs a managed PostgreSQL with connection pooling, backups, and GDPR data residency in the EU.

## Decision

**Development**: `sqlite+aiosqlite:///./aria_dev.db` — zero configuration, fast, in-process.

**Integration tests**: `sqlite+aiosqlite:////:memory:` — fully isolated, fastest possible setup.

**Production**: `postgresql+asyncpg://...@supabase-host/aria` (Supabase managed PostgreSQL 16).

The same SQLAlchemy async models and Alembic migrations work unchanged across both engines. The only difference is the `DATABASE_URL` in `.env`.

**Why Supabase** (over raw Fly.io PostgreSQL):
- Managed PostgreSQL with generous free tier ($0 → $25/month)
- Built-in connection pooling via PgBouncer — critical for the shared Fly.io container
- EU region available (Frankfurt) — GDPR data residency
- SQL-standard, so SQLAlchemy works identically to SQLite
- pgvector extension available for future semantic search on session transcripts

## Consequences

**Positive**:
- Unit tests run with zero infrastructure (no Docker needed)
- SQLite → PostgreSQL migration is a single env var change
- Supabase connection pooling handles the Fly.io container's connection limits

**Negative/Risk**:
- SQLite and PostgreSQL have minor dialect differences (e.g., `JSON` type handling)
- Alembic autogenerate may produce SQLite-incompatible migrations for PostgreSQL-specific features

**Mitigated by**: Quinn_QA runs integration tests against PostgreSQL in CI (GitHub Actions service containers). Gate 2 fails if tests pass SQLite but fail PostgreSQL.

## Alternatives Rejected

| Alternative | Why rejected |
|---|---|
| PostgreSQL for dev too | Requires Docker running for every dev session; overkill for unit tests |
| PlanetScale (MySQL) | MySQL dialect differences from PostgreSQL; Supabase has better FastAPI ecosystem support |
| CockroachDB | Distributed overhead not needed at Aria's scale; higher complexity |
