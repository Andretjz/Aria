# ADR-001: STT Provider Selection

**Status**: Accepted
**Date**: 2026-05-16
**Decided by**: Sam_Architect + Claude gate review

## Context

Aria requires two distinct STT use cases with different requirements:

1. **Live conversation** (Modules 1 & 2): Real-time streaming, <600ms first-partial latency, natural conversation cadence.
2. **Batch analysis** (uploaded files, post-session): Accuracy over latency; higher tolerance for processing time.

Constraints: GDPR compliance for EU users; support for 5 target languages (de/en/es/fr/it) with strong WER; cost-effective at scale.

## Decision

| Mode | Dev | Production |
|---|---|---|
| Live streaming | faster-whisper large-v3-turbo (local GPU) | Gladia WebSocket (primary), Deepgram Flux (fallback) |
| Batch / uploaded files | faster-whisper large-v3-turbo (local GPU) | Deepgram Nova-3 |

**Gladia** is the primary production live-STT provider because:
- GDPR-native (France-based) — no DPA setup needed for EU users
- 270ms streaming latency (comparable to Deepgram Flux <300ms)
- 100+ language support including all 5 target languages
- Built-in diarization in the same API call (eliminates a separate service)
- ~$0.20–0.75/hr competitive pricing

**Deepgram Nova-3** is the batch/fallback provider because:
- 5.9% WER English, 6.8% multilingual — best accuracy at this price point
- $0.0077/min
- Identical WebSocket interface to Gladia → adapter swap is one class

**Automatic fallback**: If Gladia returns 3 consecutive errors, the STT service switches to Deepgram and logs the incident. No manual intervention required.

## Consequences

**Positive**:
- GDPR-native primary provider simplifies EU compliance
- Adapter pattern means swapping providers = one .env line change
- Automatic fallback ensures uptime if Gladia has issues

**Negative/Risk**:
- Gladia is a smaller company than Deepgram — longevity risk
- Two providers = two SDK dependencies to maintain

**Mitigated by**: Both providers implement the same `STTService` abstract interface. If Gladia were to shut down, switching permanently to Deepgram requires changing `STT_BACKEND=deepgram` in `.env` only.

## Alternatives Rejected

| Alternative | Why rejected |
|---|---|
| OpenAI Whisper API | Not streaming-optimised; batch only; +latency not acceptable for live conversation |
| Speechmatics Enhanced | +734ms streaming latency vs Flux — breaks natural conversation cadence |
| AssemblyAI Universal-2 | +761ms latency, worse multilingual WER than Deepgram at same price |
| Self-hosted Whisper (prod) | GPU-dependent in production; contradicts the no-GPU-in-prod constraint |
